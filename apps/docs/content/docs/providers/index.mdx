OpenMausBot does not proxy every message through its own model account. It starts supported agent CLIs on your computer and normalizes their output through the local harness.

## Built-in engines

| Engine | Authentication shape | Notes |
|---|---|---|
| Claude | Claude CLI login | Strong support for tools, approvals, and sessions |
| Codex | Codex CLI login | Model discovery, approvals, and steering |
| Grok | Grok CLI login | ACP-based local model catalog and session support |
| Cursor | Cursor Agent CLI login or API key | ACP driver with live model discovery |
| Kimi | Kimi CLI login | ACP integration |
| Droid | Factory Droid CLI login | ACP integration |
| OpenCode | Existing OpenCode provider login or optional API key | Live Zen, Go, third-party, and local model discovery through ACP |
| Qwen | Qwen CLI login | ACP integration |
| Hermes | Hermes CLI login | ACP integration |
| Pi | Pi CLI login | Native driver |

Additional driver instances can be declared in local configuration. Unavailable engines remain visible with a reason instead of crashing the provider fleet.

To use OpenRouter, Fireworks AI, DeepSeek, Cline, or your own OpenAI- or Anthropic-compatible service, see [Other model providers](./model-providers.mdx).

Codex models come from the signed-in CLI's live model list. If that list cannot be read, the picker shows an offline fallback that includes GPT-6 Astra, Sol, and Luna with availability marked unverified. An older CLI may not expose newer models; OpenMausBot checks for a newer stable Codex release and offers an update command for the configured executable. Updating the CLI does not grant model access to an account.

## Mistral API

Open **Settings → Connections**, save your **Mistral API key**, then choose **Mistral (API)** in a bot's model picker. No CLI installation is needed. The **Test** button checks catalog access without sending a chat message.

The model list refreshes from Mistral's `/v1/models` endpoint, including versioned models and aliases. Archived and non-chat models are excluded. Use **Refresh models** after new models become available to your account; an unsuccessful refresh preserves the previous list. Mistral bills requests to your API account.

For a server deployment, set `MISTRAL_API_KEY` or save `mistral.key` in the server configuration. Advanced users can declare additional `mistral` instances with a `config.model` default and endpoint URL. A saved workspace key is shared by those instances. The connection supports streamed replies and structured tools through the shared chat-completions runtime; it does not launch a local agent CLI or grant filesystem access.

## Detection

OpenMausBot checks common installation directories and the login shell in the background. Restart the app after installing or authenticating a CLI.

If detection fails, use **Settings → Engines** to set an explicit executable path. This is supported for every engine and is the most reliable solution for version managers, wrappers, custom builds, and Windows installations outside the normal path.

## Model selection

The model picker groups models by provider and marks defaults. Supported engines can refresh their model catalog from the installed CLI. Changing the model affects future turns; it does not rewrite earlier transcript history.

## Codex desktop-only tools

Desktop-only Codex browser/computer features and their bundled plugins are disabled
for Codex bot processes, so bots do not select a native desktop connection that is
unavailable inside the CLI. This does not uninstall plugins or change the standalone
Codex app. Native web search keeps its configured mode.

## Claude login

Claude bots use the Claude Code login of the computer hosting OpenMausBot: `~/.claude`, or the directory `CLAUDE_CONFIG_DIR` names for the OpenMausBot process. Sign in there with `claude auth login`; Settings → Engines shows that command while Claude is not signed in and reads its status again on **Check again**. OpenMausBot keeps no Claude accounts of its own.

<Callout type="info" title="Subscriptions stay with the provider">
  Your existing CLI login or provider API key determines access and billing. OpenMausBot does not turn one subscription into access to another provider.
</Callout>
